# 경로·터널 연산 백엔드 이관 명세

프론트(웹·모바일)가 지금 브라우저에서 직접 호출하는 외부 서비스를 백엔드로 옮기기 위한 명세다.
백엔드(Ma_BE)는 이 저장소에서 수정하지 않으므로, 아래 계약대로 엔드포인트가 생기면 프론트는
`src/lib/route.js`와 `src/lib/tourSafety.js` 두 모듈의 내부 구현만 바꿔 붙일 수 있다.

## 왜 옮겨야 하나

| 문제 | 지금 | 옮기면 |
|---|---|---|
| 공개 데모 서버 의존 | Valhalla FOSSGIS 데모 서버를 브라우저에서 직접 호출. 상용 트래픽 금지·SLA 없음 | 자체 호스팅 Valhalla를 백엔드가 프록시 |
| 키 노출 | 모바일 번들에 카카오 REST 키가 박힘 | 키를 서버에만 두고 프록시 |
| 중복 연산 | 같은 도로의 터널 구간을 기기마다 매번 계산 | 경로 단위 캐시로 1회 |
| 관광지 추천 지연 | 한 번 열 때 외부 API를 70여 회 호출, 완료까지 40초 이상 | 사전 계산 테이블 조회로 즉시 |

## 프론트가 계속 들고 있어야 하는 것

주행 루프(0.5초 간격 위치 갱신), 터널 진입·통과 판정, 터널 안 추측항법, 지도 렌더, 호흡 가이드는
**백엔드로 보내면 안 된다.** 터널 안에서는 GPS와 통신이 동시에 끊기는데, 사용자가 앱을 가장
필요로 하는 순간이 바로 그때다. 서버 왕복에 의존하면 그 순간 앱이 멈춘다.

백엔드가 맡을 것은 "출발 전에 한 번 계산하면 되는 것"뿐이다.

## 1. 경로 + 터널 구간

```
POST /api/routes
{
  "origin":   { "lat": 37.6971, "lng": 127.8888 },
  "dest":     { "lat": 38.1889, "lng": 128.6021 },
  "waypoints": [ { "lat": ..., "lng": ... } ],     // 없으면 빈 배열
  "avoidTunnels": false                             // true면 터널 완전 배제 경로
}
```

```json
{
  "success": true,
  "data": {
    "path": [[37.6971, 127.8888], [37.6972, 127.8890]],
    "maneuvers": [{ "idx": 0, "type": 1, "street": "석화로" }],
    "distanceKm": 104,
    "durationMin": 81,
    "tunnels": [
      { "name": "화촌3터널", "lengthM": 527, "diff": 3, "startM": 20480, "endM": 21007 }
    ]
  }
}
```

핵심은 `tunnels`다. 프론트는 이미 이 형태(`{name, lengthM, diff, startM, endM}`)로 터널을 다루므로
그대로 내려주면 내비게이션 화면은 손대지 않아도 된다.

- `startM` / `endM` : 경로 시작점부터의 **누적 이동거리(m)**. `path`를 순서대로 이은 거리이며,
  프론트의 진입·통과 판정이 이 값만 쓴다. 인덱스가 아니라 거리로 주는 것이 중요하다.
- `diff` : 공황 난이도 1~5. 강원도 터널 데이터셋에 있으면 그 값, 없으면 길이로 추정한다
  (6km↑ 5, 3km↑ 4, 1km↑ 3, 500m↑ 2).
- 500m 미만 터널은 빼도 된다. 프론트가 동반 모드를 띄우지 않는 구간이다.

구현 시 주의할 점 두 가지는 프론트에서 실제로 겪은 버그다.

1. **이어지는 터널만 합칠 것.** 짧은 노출 구간을 사이에 둔 이웃 터널까지 합치면 기린6터널(2.6km)과
   인제양양터널(10.9km)이 13.6km 한 덩어리가 된다.
2. **이름은 OSM `tunnel:name`에서 가져올 것.** Valhalla가 주는 `edge.names`는 도로명뿐이라
   전부 "서울양양고속도로"로 나온다.

## 2. 지오코딩

```
GET /api/geocode?query=속초해수욕장
GET /api/geocode/reverse?lat=37.69&lng=127.88
```

```json
{ "success": true, "data": { "lat": 38.1889, "lng": 128.6021, "name": "속초해수욕장", "address": "강원특별자치도 속초시 조양동" } }
```

카카오 REST 키를 서버에만 두는 것이 목적이다. 결과 없으면 `data: null`.

## 3. 관광지 안심 지수

```
GET /api/spots?lat=37.69&lng=127.88
```

```json
{
  "success": true,
  "data": [
    { "id": "s1", "name": "속초해수욕장", "region": "속초", "category": "해변",
      "lat": 38.18892, "lng": 128.60214, "desc": "...", "indoor": false, "season": "여름",
      "score": 72, "tunnelCount": 4, "totalTunnelM": 5120,
      "longest": { "name": "화촌9터널", "lengthM": 3704 },
      "distanceKm": 104, "durationMin": 81 }
  ]
}
```

관광지 목록은 `src/data/tourSpots.js`(36곳)에 있다. 점수 공식은 `src/lib/tourSafety.js`와 맞춘다.

```
score = 100 − min(55, 총터널km × 5.5) − min(25, 터널개수 × 2.5)
```

출발지는 100m 격자로 반올림해 캐시 키로 쓰면 적중률이 높다. 야간 배치로 시군 대표 좌표만
미리 계산해 두어도 충분하다.

## 4. 인프라

- **Valhalla 자체 호스팅**: Docker + 한국 OSM 추출본. 백엔드는 `valhalla.base-url` 설정으로
  업스트림만 바꿀 수 있게 두면 데모 서버 → 자체 호스팅 전환이 설정 변경으로 끝난다.
- **캐시 저장소**: 지금 H2 인메모리라 재시작하면 캐시가 날아간다. 파일 기반 H2나 별도 DB가 필요하다.
- **인증**: 위 세 엔드포인트는 로그인 없이 쓰는 화면에서도 호출되므로 `SecurityConfig`의
  `permitAll` 목록에 넣어야 한다.

## 전환 순서

1. Valhalla 자체 호스팅 또는 프록시 — 서비스가 죽을 수 있는 유일한 항목이라 가장 급하다
2. 지오코딩 프록시 — 키 노출은 되돌릴 수 없다
3. 터널 구간 캐싱
4. 관광지 안심 지수 사전 계산

## 프론트 전환 지점

외부 서비스를 직접 부르는 곳은 아래 네 곳뿐이다. 엔드포인트가 준비되면 이 파일들의 내부만 바꾼다.

| 파일 | 지금 호출하는 곳 |
|---|---|
| `src/lib/route.js` | Valhalla `/route`, `/trace_attributes`, OSM `ways.json` |
| `src/lib/tourSafety.js` | 위 모듈을 관광지 수만큼 반복 호출 |
| `src/lib/kakaoMap.js` | 카카오 지도 JS SDK (지도 렌더용이라 클라이언트 유지) |
| `mobile/src/lib/kakaoRest.js` | 카카오 Local REST, Photon 폴백 |

`mobile/src/lib/route.js`는 웹과 같은 구현이라 함께 바꾼다.
